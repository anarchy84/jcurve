> 사이트의 **모든 이미지·영상은 힉스필드로 생성**한다(대웅 지시 2026-08-04).
> 이 문서 = 미디어 슬롯 인벤토리 + 슬롯별 힉스필드 프롬프트 + 규격 + 배치 경로 + 생성 순서.

## 0. 공통 아트디렉션 (전 미디어 관통 — design-system.md 톤)

디자인시스템: "미술관 갤러리형. 사진·영상이 주인공. 장식 그라디언트 없음. 인터랙션 컬러는 액션블루 하나."

### 모든 힉스필드 프롬프트에 공통으로 넣는 톤 블록
```
Apple editorial style, museum-gallery minimalism, cinematic product photography,
near-black (#0a0a0c) or clean white studio background, single accent color
electric blue (#0066cc ~ #2997ff) used sparingly, soft directional light,
shallow depth of field, ultra-clean composition, generous negative space,
no decorative gradients, no logos, no on-screen text, no korean characters,
premium tech brand aesthetic, 8k, photorealistic
```

### ⚠️ 절대 규칙 (메모리 학습 반영)
- **텍스트/글자 금지** (`no text, no letters, no korean`) — AI 생성 한글은 깨진다. 글자는 전부 CSS로 얹는다.
- **로고 금지** — 실제 클라이언트 로고는 진짜 파일로. AI 생성 금지.
- **증거성 이미지 금지** — 성과 스샷·대시보드 실측은 AI로 만들지 않는다(조작 리스크). work/insight 실데이터 비주얼은 실제 캡처.
- 애플 톤이라 **채도 낮게, 블루 포인트 1개만**. 여러 색 쓰면 디자인시스템 위반.

### 모델 선택 기준
| 용도 | 모델 | 비고 |
|---|---|---|
| 추상·제품·브랜드 비주얼(대부분) | `marketing_studio_image` | 커머셜 톤, 2크레딧/장 |
| 4K·정밀 필요 | `nano_banana_pro` | 히어로 poster 등 |
| 히어로 영상(6초 루프) | `kling3_0_turbo` (start_image 기반) | 스틸 먼저 뽑고 애니메이트 |

### 규격·경로 표준
| 슬롯 유형 | 비율 | 파일 경로 |
|---|---|---|
| 홈 히어로 영상 | 16:9, 6초 루프, 1080p | `public/media/hero.mp4` (+`.webm`, `hero-poster.jpg`) |
| 섹션 타일 이미지 | 16:9 | `public/media/sections/{이름}.webp` |
| 솔루션 제품 이미지 | 4:3 | `public/media/solutions/{이름}.webp` |

| 인사이트/성과 커버 폴백 | 16:9 | `public/media/covers/{주제}.webp` |
> 힉스필드 산출 → WebP 변환(품질/CWV) 후 위 경로. poster는 LCP용 필수(PLAN 7장).

## 🎬 생성 순서 (우선순위 · 크레딧 관리)

**1차 — 톤 확정용 대표 4개** (지금 생성)
```
M1 홈 히어로 스틸 · M2 퍼포먼스 · M3 CPA·리워드 · M4 SEO·AI
→ 대웅 톤 확정 후 나머지 진행 (톤 틀리면 여기서만 재작업, 크레딧 절약)
```
**2차 — 톤 OK 후 배치**
```
M5, M6~M10(서비스 5), M11~M14(솔루션 4), M15(회사)  = 이미지 11장 (~22크레딧)
```
**3차 — 커버 6종**
```
M16~M21  = 6장 (~12크레딧)
```
**4차 — 히어로 영상**
```
M1 스틸 → kling3_0_turbo 애니메이트 → hero.mp4/webm (영상 크레딧 별도, 비쌈)
```

### 예상 크레딧 (이미지 2크레딧/장 기준)
- 1차 4장 = 8 · 2차 11장 = 22 · 3차 6장 = 12 → **이미지 총 42크레딧**
- 히어로 영상 = 모델별 별도(생성 시 get_cost로 확인)
> 톤 확정 전엔 1차 8크레딧만 쓴다. 하네스 원칙: 검수 없이 전량 생성 = 낭비 리스크.
