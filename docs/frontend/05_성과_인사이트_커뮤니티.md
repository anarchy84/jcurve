# 1. 성과 (Work) — `/work`, `/work/{slug}`

**목적**: 로고월이 "누구와"라면, work는 "얼마나". **숫자 중심 케이스**. B2B 신뢰의 핵심.

## 1-1. 목록 `/work` [아키타입 C]

```
[파치먼트] 페이지 헤더
  H1:   성과
  리드:  캠페인은 끝나도 데이터는 남습니다. 숫자로 증명된 결과들입니다.
  필터:  전체 · 퍼포먼스 · CPA · SEO · 리워드   (industry/service 태그 기반, 선택)

[라이트] 성과 카드 그리드 (2~3열, 반응형)
  카드 = [썸네일 16:9] + 클라이언트·산업 + 대표 지표 1개(크게) + 제목
  예:   [썸네일]
        패션 이커머스 · 퍼포먼스
        ROAS 340%        ← 대표 지표를 카드에서 가장 크게 (display)
        "광고비 절반으로 매출 2배"
```

**카드 지표 규칙 (Evidence Guardian)** ⚠️
- 지표는 **works.metrics(json) 실데이터만.** 시드 없으면 **숫자 카드를 만들지 않는다**(허위 금지).
- 클라이언트명 노출은 **NDA 확인 필요.** 비공개면 "패션 이커머스 A사"처럼 익명화.
  → 클로드코드: `client` 필드가 공개가인지 플래그(`client_public`) 두거나, 우선 산업명만 노출.

**빈 상태 (empty)** — 지금 "등록된 포트폴리오가 없습니다"는 밋밋. 개선:
```
아직 공개된 성과 사례를 준비 중입니다.
지금 진행 중인 마케팅의 성과가 궁금하시면 —  [무료 진단 요청 →]  (→ contact)
```
> 빈 상태를 **리드 유입구로** 전환(하네스 Growth 관점). 그냥 "없음"으로 끝내지 않는다.

## 1-2. 상세 `/work/{slug}` [아키타입 D + 지표 강조]

```
[파치먼트] 히어로:  클라이언트·산업 + 제목 + 대표 지표 3개(가로 나열, 크게)
[라이트]   배경:    "어떤 문제였나" (도전 과제)
[라이트]   접근:    "무엇을 했나" (전략·실행)
[파치먼트] 결과:    지표 상세 (before→after, metrics json 전개) + 그래프(선택)
[라이트]   고객 반응: 인용(있으면)
[다크]     CTA:     "비슷한 결과가 필요하신가요?"  [프로젝트 문의]
관련:      같은 산업/서비스 사례 2 + 관련 서비스 페이지 1 (PLAN 내부링크)
```
- 성과 상세는 **[문제→접근→결과] 3막**. 결과는 반드시 숫자.
- 이미지엔 product-shadow(디자인시스템 유일 그림자).

# 2. 인사이트 (Insights) — `/insights`, `/insights/{slug}`, `/insights/category/{slug}`

**목적**: SEO 콘텐츠 엔진(PLAN). **301로 기존 칼럼 50편 + WP 아티클 3편이 여기로 유입.**
→ 빈 페이지가 아니라 **이미 콘텐츠가 있는 상태로 런칭**된다(URL-MIGRATION). 목록 UX가 중요.

## 2-1. 목록 `/insights` [아키타입 C]

```
[파치먼트] 페이지 헤더
  H1:   인사이트
  리드:  현장에서 검증한 것만 글로 남깁니다.
  카테고리 탭:  전체 · 퍼포먼스 · 페이스북 · 인스타그램 · 구글 · 브랜딩 · 콘텐츠
              (insight_categories 기반, URL-MIGRATION B-1 매핑과 일치)

[라이트] 아티클 카드 그리드 (2~3열)
  카드 = [커버 16:9] + 카테고리 칩 + 제목 + 발췌 2줄 + 날짜
  (커버 없으면 텍스트 카드 — 제목 크게, 카테고리색 좌측 바)
```
- 첫 진입 시 **최신순.** 카테고리 탭은 `/insights/category/{slug}`로 이동(SEO 개별 URL 유지).
- 페이지네이션은 하단(Laravel 기본, 링크색 --primary).

**빈 상태**: 칼럼 50편 이식되면 안 비지만, 카테고리별로 0건일 수 있음:
```
이 카테고리의 글을 준비 중입니다.  [전체 인사이트 보기 →]
```

## 2-2. 상세 `/insights/{slug}` [아키타입 D]

```
[라이트] max 980px 리딩
  카테고리 칩 + H1 + 메타(작성자·날짜) + 리드(발췌, 28px muted)
  본문 (17px/1.6, 이미지 product-shadow)
  ── 하단 ──
  · 관련 서비스 CTA 블록 (본문 주제 → 해당 /services 페이지, PLAN 내부링크)
  · 관련 인사이트 3
  · [목록으로]
```
- ⚠️ 이식 콘텐츠(칼럼 50편)는 **원문 100% 보존**(URL-MIGRATION §E, 소프트404 방지). 리라이팅 금지.
- 본문 내 "문의" 링크는 자동으로 파란 pill(app.css 기존 규칙).

# 3. 커뮤니티 (Community) — `/community`, `/community/{board}`, `/community/{board}/{id}-{slug}`

**목적**: 마케터 커뮤니티(회원제). PLAN DB: boards / posts / comments / likes.
**성격 주의**: 마케팅 방문자(리드) 흐름과 **분리**. 커뮤니티는 회원 공간, 마케팅 페이지는 세일즈. 시각 톤 구분.

## 3-1. 게시판 허브 `/community` [아키타입 C]

```
[파치먼트] 헤더
  H1:   마케팅 커뮤니티
  리드:  실무자들이 묻고 답하는 공간입니다.
  (로그인 상태 아니면) [로그인] · [회원가입]  — 우측 작게

[라이트] 게시판 카드 (board-list, 이미 구현)
  카드 = 게시판명 + 설명 + (선택)최근 글 1~2개 미리보기 + 글 수
  게시판 4종(PLAN): 자유(free) · 질문답변(qna) · 팁·노하우(tips) · 공지(notice)
```

## 3-2. 게시판 `/community/{board}` [테이블]

app.css에 board 테이블 스타일 이미 있음. 구조:
```
[파치먼트] 게시판 헤더: 게시판명 + 설명 + [글쓰기](로그인 시) 
[라이트]   공지 영역(is_notice, 파치먼트 배경 강조) 
           글 목록 테이블: 제목 · 작성자 · 날짜 · 조회 · 좋아요
           (모바일: 테이블 → 카드형 전환, 제목+메타 세로)
           페이지네이션
```
- 비회원도 **읽기 가능**(SEO·유입), 쓰기는 로그인(PLAN write_permission).
- 검색·정렬(최신/인기) 상단 바(선택).

## 3-3. 글 상세 `/community/{board}/{id}-{slug}` [리딩 + 상호작용]

```
[라이트] max 980px
  제목 + 메타(작성자·날짜·조회) + [좋아요 N](토글, 로그인)
  본문 (markdown 렌더, 17px/1.6)
  ── 댓글 (2단 중첩, app.css 이미 구현) ──
  댓글 입력(로그인) · 댓글 리스트 · 대댓글 1depth
  ── 하단 ──
  [목록으로] · 이전글/다음글
```
- 비로그인: 본문·댓글 **읽기 가능**, 작성 시 로그인 유도(모달 또는 인라인).
- 좋아요/댓글 수는 비정규화 컬럼 반영(PLAN, N+1 방지).
- ⚠️ 스팸: honeypot(PLAN 패키지) + 레이트리밋. 신규 글/댓글에 적용.

## 공통 UX 규칙 (3영역 전부)

| 항목 | 규칙 |
|---|---|
| 카드 그리드 | 1068px↓ 2열, 833px↓ 1열 (디자인시스템 브레이크포인트) |
| 썸네일 | aspect-ratio 16:9 예약(CLS 0), 없으면 텍스트 카드 폴백 |
| 카드 호버 | translateY(-4px) + border --ink (app.css 기존 패턴 재사용) |
| 빈 상태 | "없습니다"로 끝내지 않고 **다음 행동 링크** 제공 (하네스 Growth) |
| 날짜 | `<time datetime>` 시맨틱 (SEO·접근성) |
| 목록→상세 | 카드 전체가 클릭영역(제목만 아님) |
