# 카카오톡 상담 — 현황 확인과 Claude 프론트 인계

작성: Codex · 2026-10-27 · 상태: 확인·추가 방식 검토 완료 / 실제 상담 채널 URL 확인 대기. 사용자 요청은 ‘카카오톡 상담도 달아야 하는데 확인’이며 이번에는 제품 코드·카카오 계정/채널 설정·서버를 변경하지 않았다. 배포 금지를 유지한다.

## 확인한 사실

| 대상 | 확인 결과 | 범위와 한계 |
|---|---|---|
| 로컬 `resources`, `app`, `config`, `routes`, `.env.example` | 상담용 카카오톡 채널 URL·버튼·설정이 검색되지 않음 | 카카오 선물하기 마케팅 페이지·제휴사 이름은 상담 연동과 구분 |
| `database/content`, `public` | `pf.kakao.com`, `open.kakao.com`, `plus.kakao.com` 상담 URL이 검색되지 않음 | 빌드 산출물·SVG·소스맵은 제외. 카카오 관리자 계정은 조회하지 않음 |
| [기존 홈페이지](https://j-curve.co.kr/) | 공개 GET200, 정적 HTML에서 위 카카오 상담 URL 없음 | 제목 ‘구글 네이버 SEO 업체 / 검색엔진 최적화 전문 / 제이커브’. 동적 위젯/실기기 앱 진입까지 확인한 것은 아님 |
| [기존 상담신청](https://j-curve.co.kr/contact-us/) | 공개 GET200, 정적 HTML에서 위 카카오 상담 URL 없음 | 기존 문의 채널은 유지 대상 |
| 새 문의 화면 `resources/views/contact.blade.php` | 프로젝트 문의 폼·접수 후 안내·FAQ 중심, 카카오 상담 버튼 없음 | `GET /contact`, `POST /contact` 기존 경로 유지 |
| 공통 푸터 `resources/views/partials/jc/footer.blade.php` | 고객센터 메뉴·전화·이메일 표기, 카카오 상담 링크 없음 | 새 레이아웃 `layouts/jc`와 기존 페이지용 `layouts/app` 모두 적용을 확인해야 함 |

검색으로 제이커브 소유임을 확인할 수 있는 공식 채널을 찾지 못했다. 검색에 안 나온다는 이유로 채널 자체가 없다고 결론내리지는 않는다. 사용자에게 사용할 채널 홈/채팅 URL을 요청했다. 외부 동명이인 채널이나 랭크프리 등 다른 서비스의 채널을 임의 연결하지 않는다.

## 권장 연결 방식

**1차는 공식 카카오톡 채널의 관리자 발급 ‘채팅 URL’을 일반 링크 버튼에 연결**하는 방식이 적합하다. 클릭 전에는 별도 채팅 SDK를 로드하지 않고, 웹사이트는 카카오의 연결 페이지로 이동시킨다. 링크 이동만 제공하는 이 범위에는 새로운 회원 인증·DB·주문 API가 필요하지 않다. 이 설명은 현재 소스와 링크 방식에 대한 구현 제안이며 실제 연결 완료 보고가 아니다.

카카오 공식 관리자 가이드는 채널 홈 URL과 채팅 URL을 구분하고, 채팅 URL이 채팅방에 연결되며 PC/모바일에서 각각 연결 절차를 거친다고 설명한다. 관리자가 실제 발급한 URL을 우선 사용한다. [카카오톡 채널 관리자센터 공식 이용 가이드](https://t1.daumcdn.net/rocket/user-guide/user-guide.pdf)

공식 SDK로 구현하는 대안도 있다. `Kakao.Channel.createChatButton()` 또는 `Kakao.Channel.chat()`을 쓰며 SDK 설치·초기화·JavaScript 키·도메인 설정이 필요하다. 현재 목표인 상담 진입 링크보다 도입 범위가 커지므로 1차 기본안으로 요구하지 않는다. [카카오 공식 JavaScript 채널 채팅 문서](https://developers.kakao.com/docs/ko/kakaotalk-channel/js)

버튼은 카카오톡 1:1 상담으로 진입하는 수단이다. 사이트 안에 대화창이 내장되는 기능, 챗봇 자동 답변, 상담원 배정·CRM 수집, 알림톡 발송까지 구현한 것으로 안내하지 않는다.

## Claude가 반영할 화면 제안

| 위치 | 표시와 역할 |
|---|---|
| 공개 페이지 공통 오른쪽 아래 | 말풍선 아이콘 + **카카오톡 상담**. 데스크톱·모바일에서 같은 채널 사용 |
| `/contact` 문의 페이지 | **카카오톡으로 상담하기**와 기존 프로젝트 문의 폼을 함께 제공 |
| 고객센터 메뉴·푸터 | **카카오톡 상담** 진입점 추가 |
| 셀프마케팅·리워드 서비스 | 필요 시 **집행 전 상담하기** 같은 보조 CTA. 실제 주문 버튼과 동작 구분 |

- 헤더/본문/모바일 메뉴/문의 폼·버튼을 가리지 않도록 배치한다. 모바일 safe-area·키보드·고정 하단 UI를 고려하고 터치 영역은 최소44px로 잡는다.
- 가리키는 곳은 채널 소개가 아니라 실제 상담 가능한 채팅 URL이다. 실제 URL 확인 전에는 카카오 버튼을 숨기고 기존 `/contact` 진입점을 유지한다. `#`, 임의 채널, 가짜 URL로 활성 버튼을 만들지 않는다.
- 공개 URL 하나를 공통 설정/데이터 원본에서 읽도록 설계해 페이지마다 하드코딩하지 않는다. 최종 소유 경로와 계약이 필요하면 Codex에 요청한다. 공개 상담 URL은 API 키나 비밀값이 아니다.
- 외부 링크는 의미 있는 `<a>`와 접근 가능한 이름으로 제공한다. 새 창을 쓸 경우 안내와 `rel="noopener noreferrer"`를 넣는다. JS가 차단되거나 분석 이벤트가 실패해도 링크 이동이 동작해야 한다.
- 실제 확인 전 ‘24시간 상담’·‘즉시 답변’·‘상담원 접속 중’ 표시를 만들지 않는다. 운영시간·부재중 응답은 채널 운영 설정과 일치하는 경우에만 안내한다.
- 로그인/결제/키 입력/관리자 화면에는 필요성을 별도로 판단하고, 특히 민감 입력 중 화면을 덮는 팝업이나 자동 대화창은 띄우지 않는다.
- 기존 URL·canonical·title·본문·301·sitemap을 상담 버튼 추가 때문에 바꾸지 않는다. 상담 버튼 자체가 검색 순위 상승이나 GEO 인용을 보장한다고 설명하지 않는다.

## 측정 제안

버튼 클릭 이벤트는 `kakao_consult_click`으로 통일하고 위치(`floating`, `contact`, `footer`, `service`)·서비스 분류·query 없는 페이지 경로만 전달하는 방식을 제안한다. 키·비밀번호·문의 내용·연락처·URL query 값은 넣지 않는다. 중복 이벤트를 막고 분석 요청 완료를 기다리느라 링크 이동을 지연시키지 않는다.

지정 공통 head/layout/JS/config 검색에서 `gtag`·`dataLayer` 초기화를 확인하지 못했다. 실제 GA4 설치·동의 설정은 별도 확인 후 연결해야 하며 이번 확인을 ‘GA4 전환 추적 설치 완료’로 집계하지 않는다.

**클릭은 상담 시작/문의 접수/유효 리드와 구분한다.** 카카오 공식 SDK도 함수 호출 결과로 채팅방 진입 성공을 알려주지 않는다고 명시한다. 클릭만으로 `generate_lead`·실제 상담 건수를 올리지 않는다. 실제 상담/계약 전환은 별도 운영 데이터와 검수된 연결 방식이 필요하다. [카카오 공식 채팅 응답 계약](https://developers.kakao.com/docs/ko/kakaotalk-channel/js)

## 필요한 확인과 역할

1. 사용자: 제이커브 상담용 실제 채널 홈 또는 관리자 발급 채팅 URL. 채널이 없다면 그 사실을 먼저 확인한다.
2. 채널 담당자: 채널 표시명/사업자 소유·공개 상태·1:1 채팅 가능 여부·운영시간·부재중 안내를 확인한다. 이번에 카카오 관리자 설정을 변경하지 않았다.
3. Claude: 공통 버튼·문의/고객센터 배치·모바일/접근성·필요 시 클릭 이벤트 화면 구현. 프론트 파일 소유권을 유지한다.
4. Codex: 필요한 공통 설정/서버 계약을 합의 후 구현하고, 프론트 완성 후 링크 목적지·비노출 조건·기존 문의 동작을 별도로 검증한다.

채널 URL이 확인되면 실제 상담 대상이 제이커브인지 먼저 확인하고, 로컬에서 링크·표시·실기기 앱/브라우저 진입을 검수한다. 실제 상담 메시지를 보내거나 채널을 새로 생성·연결·변경하는 작업은 이번 확인에 포함하지 않는다.

## 작업 기록

- 코드/이관 데이터 검색, 기존 운영 홈페이지·상담신청 HTML의 GET 결과, 카카오 공식 문서를 확인했다. 첫 웹 도구의 운영 홈 조회는 timeout이었으나 별도 공개 HTTP GET으로200과 링크 검색 결과를 확인했다.
- 분업 규칙상 Claude 프론트 구역은 수정하지 않았다. 제품 코드·`.env`·실제 카카오 계정/채널·DB·서버·커밋/푸시·배포/발행 변경 없음.
- 문서 검토 작업이므로 앱 테스트를 실행한 결과를 추가하지 않는다. 모바일 실기기·실채널 채팅·실제 GA4 이벤트 수집은 미검증이다.
