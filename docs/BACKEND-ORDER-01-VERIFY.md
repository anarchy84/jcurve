# BACKEND-ORDER-01 독립 검증 지시서

사용자 지시: 셀프마케팅 주문은 기존 랭크프리 API를 **서버에서만** 호출한다. 서버 반영·실제 주문·키 입력은 미승인이다. 고객별 계정 vs 제이커브 통합 계정 질문은 아직 미답이다. 이번 구현은 공개 라우트 없는 공통 서버 모듈에 한정한다.

## 경계와 소유

검토: `app/Services/Rankfree/*`, `config/rankfree.php`, `tests/Feature/RankfreeClientTest.php`, `.env.example`의 RANKFREE 설정 추가, `docs/BACKEND-ORDER-01.md`.

제품·테스트 수정 금지. 공유 작업 폴더이므로 타인 변경을 되돌리지 않는다. `.env` 열람·로딩 금지. 외부 API·실제 주문·실제 DB·배포·git 변경·프론트·미디어 수정 금지. 임시 폴더에서 config를 격리하고 모든 HTTP는 fake/preventStrayRequests로 막는다. 부모는 대시보드를 담당한다.

검증자는 결과 보고서 `docs/BACKEND-ORDER-01-VERIFY-RESULT.md`만 소유한다. 제품 코드는 부모가 수정한다. 이 지시서를 읽은 뒤 구현 코드를 동결한 상태에서 독립 실행한다.

## 필수 검증

1. 전체 suite·소유 Pint·PHP 문법. 구현자 관측: 기준선60/402, 주문 모듈11/54. 실제 최종 수치를 별도로 기록한다.
2. 기본 플래그가 모두false, 빈 키·불량 키·비활성·미검수 상품·비활성 주문일 때 네트워크가 나가지 않는지 확인한다.
3. 허용 호스트는 고정 HTTPS 랭크프리뿐이다. 301/302/307/308 외부·내부 리다이렉트를 따라가지 않고 API 키가 URL·예외·반환 배열에 들어가지 않는지 검사한다.
4. 상품 상세의 내부필드·FILE/IMAGE·확인 안 된 상품은 고객 응답·POST에 나오지 않아야 한다. 승인키 아래 중첩/비정상 응답과 입력, 데이터형·숫자값·주문번호 경계도 공격한다. 프로토콜 위반으로 PHP TypeError나 내부 원문을 노출하면 실패다.
5. POST는 preflight GET 뒤 한 번만 전송한다. 연결 실패·5xx·리다이렉트·손상된201·엉뚱한 상품 응답을 ‘접수 여부 불명’으로 구분하고 자동 재시도하지 않아야 한다. 401/403/404/422/429는 거절이며 원문 메시지는 제거한다.
6. 생성 직후pending과 원격 최종 금액을 유지한다. GET 상태의 주문번호 불일치·알 수 없는 상태·미지 내부 필드가 안전하게 처리되는지 검사한다. 계정 간 고객 소유권은 이 모듈이 제공한다고 주장하면 실패다.
7. 라우트·DB·결제 엔진 변경이 없고, 활성화만으로 공개 주문 화면이 생기지 않음을 확인한다. 영속 중복 원장·동시 재클릭 방지는 후속이라는 한계를 유지한다.
8. **무력화 실험1회:** `RankfreeClient::request()`의 enabled 검사 블록만 임시 제거한다. `RankfreeClientTest::test_disabled_missing_key_and_submission_gate_never_contact_remote`가 실제 실패해야 한다. 이 테스트는 preventStrayRequests가 있으므로 실제 외부 연결을 하지 않는다. 반드시 try/finally로 원문 복구, SHA256 동일 확인, 복구 후 테스트 재통과를 기록한다. 부모에게 시작·복구를 알린다.

## 반환

버그는 입력·실제/기대·파일/줄·재현 테스트로 반환하고 고치지 않는다. 실제 테스트·스타일·무력화 실험·최종 파일 해시·미검증을 보고서에 보관한다. HTTP fixture는 임시 파일만이 아니라 보고서 부록에도 남겨 재현 가능하게 한다. Claude 최종 판정·실연동·주문·배포·공개 승인으로 표시하지 않는다.
